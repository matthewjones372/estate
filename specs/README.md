# Specs

Nothing is built without a spec here. Each says what is wrong, what it will not do, the shape it takes, and a stack of
entries, one per pull request, each with what proves it done.

| Spec | What |
|---|---|
| [0001](0001-the-estate-on-one-page.md) | the estate on one page: alerts with notes and silences, health, versions through the pipeline in every environment, load, links, and a debug switch that turns itself off, for any estate described by a catalog; done |
| [0002](0002-more-kinds-of-estate.md) | more kinds of estate: Grafana alerting, Elasticsearch logs, Argo CD, GitLab CI, ECS, CloudWatch and notes in DynamoDB beside the first kinds, each part a port with its kinds behind it; done, with Buildkite, Nomad and Cloud Run left for when someone asks |
| [0003](0003-stores.md) | stores: databases, queues and caches in the catalog, with stats and health from a preset per engine (Postgres, CloudNativePG, MySQL, Redis, Kafka), on the overview and a page of their own; done |
| [0004](0004-notes-that-end.md) | notes that end: removed by their author or an operator, and after `notes.keepDays`; silences for 1 hour, 6 hours, 1 day or until 09:00; done |
| [0005](0005-charts-you-can-read.md) | charts you can read: point at, step through or drag across a chart to read a time and value, shared across a service's charts; done |
| [0006](0006-pages-in-solid.md) | the pages in Solid: the same pages and tests, updating only what changed, compiled by a Bun plugin; done |
| [0007](0007-logs-on-the-page.md) | logs on the page: a service's live lines and its errors grouped by message, from Loki or the cluster, masked; done |
| [0008](0008-the-whole-of-effect.md) | the whole of Effect: HttpClient, Config, Redacted, FiberMap, Cache, DateTime, FileSystem, metrics and spans where code is hand-rolled; fixes environments added by a reload never being read; done |
| [0009](0009-trying-it-on-a-real-estate.md) | trying it on a real estate: `estate doctor` reports what each source answered and what does not fit the catalog; `readOnly: true` so trying it can change nothing; done |
| [0010](0010-a-thousand-services.md) | a thousand services: each environment's views built once and shared by every page watching it, only changed services sent, the cluster read a namespace at a time, every flow of data a `Stream`, and lanes that look services up by name; done |
| [0011](0011-staying-fast.md) | staying fast: the bench in the repository, budgets at fifty services that fail the build, and how often each source is read set per environment; done |
| [0012](0012-through-the-platform.md) | through the platform: Prometheus and Loki through Grafana's data source proxy, and Datadog for alerts, silences, load and logs; done |
| [0013](0013-jenkins.md) | Jenkins: builds from Jenkins jobs on the pipeline rail; done |
| [0014](0014-on-a-screen.md) | on a screen: `/kiosk`, signed in once with a token, read-only, environments in turn, a team's services, and a screen that says when it is stale; done |
| [0015](0015-harness-and-teamcity.md) | Harness and TeamCity: builds from TeamCity and Harness CI, deploys from Harness CD; done |
| [0016](0016-against-the-real-thing.md) | against the real thing: `bun run integration` runs Estate's readers and writers against real Prometheus, Alertmanager, Grafana, Loki, Elasticsearch, Postgres, DynamoDB Local, Jenkins, CloudWatch's alarms in LocalStack, and Kubernetes with Flux's resources in containers; done |
| [0017](0017-what-a-review-found.md) | what a review found: sign-in returns only to a path on this host, `Secure` cookies behind https, the HMAC key imported once, silences held until the manager has them, an unsilenced alert back in its own state, and `/readyz` once every source has been read; done |
| [0018](0018-jobs-and-agents.md) | jobs and agents: categories that group the overview, jobs no service owns, and AI agents with their runs, failures, model and spend against a budget; done |
| [0019](0019-what-it-costs.md) | what it costs: each entry's cost beside its health, from AWS Cost Explorer by tag, OpenCost, and the AI providers' cost reports, with a labelled live estimate of an agent's spend from its tokens; anomalies and budgets passed need someone; done |
| [0020](0020-a-map-for-many.md) | a map for many: columns as tall as their nodes need, and past twelve nodes one node a category, opened in place, one that needs someone opening itself; done |
| [0021](0021-what-an-alert-means.md) | what an alert means, and has meant: an alert's impact on users, from its rule, the catalog, or written on the page by an operator; and its history, each past firing with its silences and notes, on its card; done |
| [0022](0022-who-to-ask.md) | who to ask: the catalog's teams with their Slack or Teams channel, Confluence or Notion pages and on-call, on service pages, job lanes and the cards of alerts about what they own; done |
| [0023](0023-tell-the-team.md) | tell the team: an alert posted to its team's Slack channel from its card, once a firing, and its notes, silences and resolution following in the thread; done |
| [0024](0024-ask-an-agent.md) | ask an agent: an alert's brief, *Around this alert* (what changed near it, its dependencies, errors, history and runbook); Estate as an MCP server at /mcp, so an AI agent reads the same estate a person does; Ask AI on an alert's page through Anthropic, OpenAI, xAI, Gemini or a self-hosted model, read-only; done |
| [0025](0025-from-alert-to-context.md) | from alert to context: what is firing first on the overview and the service page, an alert's own page with what is around it and Ask AI, a link to raise an incident, and services as lanes or a grid; done |
| [0026](0026-one-read-many-pages.md) | one read, many pages: with `cluster:` set, one runner reads every source, through an Effect Cluster entity with its shard lock in the notes' Postgres, and every replica serves the same state to its pages, `/events` and `/mcp`; writes reach the owner; one process stays the default; done |
| [0027](0027-jump-to.md) | jump to: header search and ⌘K palette to open a service, store, job or agent by name across the estate; thin `/jobs/:name` and `/agents/:name` pages so every kind has an address; done |
| [0028](0028-versions-across.md) | versions across environments: on the service page, a strip of that service's version in every environment from the deploys event, with a click to switch; done |
| [0029](0029-dead-map-edges.md) | dead map edges: null/zero rate or a failing source draws solid muted red with no dash flow; done |
| [0030](0030-follow-frame-budget.md) | the follow frame budget: what a clustered Estate sends each follower, measured by `bench/frames.ts`, held to a budget in `bun run perf`, each changed part sent as a patch, series by the points they gained; done |
| [0031](0031-discovered-services.md) | discovered services: a `discover:` rule in the catalog finds labelled workloads in Kubernetes and makes each an ordinary catalog entry, checked as one, marked as found, with written entries winning by name; done |
| [0032](0032-shard-by-environment.md) | shard by environment: in a cluster, an entity per environment reads it and `"estate"` does the estate-wide work, so the reading spreads across runners; every runner follows them all; done |
| [0033](0033-discover-from-backstage.md) | discover from Backstage: a `discover:` rule finds Backstage Components and makes each a catalog entry from its owner, system, links and annotations, as spec 0031 does for Kubernetes; done |
| [0034](0034-code-health.md) | code health per service: SonarQube's quality gate, coverage and issues, and GitHub's Dependabot and code scanning alerts, shown beside each service and in amber when it needs a look; done |
| [0035](0035-some-of-the-environments.md) | some of the environments: `environments:` in the settings chooses which of the catalog's environments an Estate shows, so one catalog serves every place, each Estate needing only its own sources; done |
| [0036](0036-logs-you-can-search-and-copy.md) | logs you can search and copy: `*` and `/regex/` with matches marked, any mix of levels, each level its colour, and lines copied or saved as text with their time, pod and level; done |
| [0037](0037-an-alert-after-it-ends.md) | an alert after it ends: a page per past firing at `/alerts/:id/:startedAt` with what happened, what was around it, its errors and its load then, linked from History, Resolved today, Alerts today and the feed; done |
| [0038](0038-ask-ai-that-answers-where-the-alert-is.md) | Ask AI that answers, where the alert is: Anthropic's reply kept whole between turns so a model that thinks can call tools, the provider's message on a failure, and Ask AI on the alert's card and near the top of its page; done |
| [0039](0039-incidents-and-their-timeline.md) | incidents and their timeline: every action on a firing kept as an event with who and when, firings linked into an incident by a person, a timeline on firing and incident pages, notes that fold, and an export as Markdown or JSON; done |
| [0040](0040-ask-ai-at-a-price-worth-asking.md) | Ask AI at a price worth asking: what repeats cached, fewer and smaller rounds of tools, effort held low, and each answer's tokens and estimated cost on the card; done |
| [0041](0041-what-a-viewer-sees-of-an-answer.md) | what a viewer sees of an Ask AI answer: an answer marks whether it read logs, a viewer where logs are for operators sees that the AI answered and not what, keeping one as a note says it is for everyone, and shared answers follow what the asker may read; done |
| [0042](0042-firings-that-may-belong.md) | firings that may belong to an incident: a firing related to one of an open incident's (the same alert, service or store, or next to it on the map) and started within 30 minutes is suggested on its card and the incident's page, linked only by a person, and *Not this* kept; done |
| [0043](0043-raising-an-incident-in-the-tool.md) | raising an incident in the incident tool: an Estate incident raised in PagerDuty, then incident.io and Jira Service Management, with its firings and a link back, the tool's link and status, severity and responders read back onto its page; other tools stay a link out |
| [0044](0044-many-alerts-at-once.md) | many alerts at once: past three firing, *Needs you now* is one row an alert opening its card in place, grouped by incident and then service, with notes minimised on cards among others and the choice kept per browser; done |
| [0045](0045-alerts-for-what-is-installed.md) | alerts for what is installed: `bun.lock`'s resolved packages submitted to GitHub's dependency graph from `main`, so Dependabot's alerts cover every installed version, not only `package.json`'s ranges |
| [0046](0046-where-a-request-spends-its-time.md) | where a request spends its time: journeys in the catalog, their stages measured from a sample of Tempo's traces on each service's page, and a trace's own page in lanes or a waterfall with long waits cut short; done |
| [0047](0047-what-happened-around-an-incident.md) | what happened around an incident: versions, deploys, restarts, health and debug kept while it is open, what people did by hand written at the time it happened, its charts, logs and traces kept on close, and everything exported as a zip |
| [0048](0048-who-wrote-a-line-and-its-trace.md) | who wrote a line, and its trace: the logger and trace ID kept on each log line, by keys the catalog names, and shown on the panel with the trace linked to its page |
| [0049](0049-runbooks-on-github.md) | runbooks on GitHub: a `blob` link read as its raw file, through the contents API with the `runbooks:` token for `github.com` or raw.githubusercontent.com without one, so the brief has the runbook and not GitHub's page; done |
| [0050](0050-finding-an-incident.md) | finding an incident: *Incidents* in the header, a page listing every incident, open ones first and then closed, filtered by either, each opening its page; done |
| [0051](0051-what-an-incident-holds-and-its-summary.md) | what an incident holds, and its summary: *Include in incident* on charts, picked log lines, error groups and traces, kept with who and why; evidence above the firings; and *Summarise*, an account of the incident from the same model and budget as Ask AI |
| [0052](0052-a-spike-on-the-load.md) | a spike on the load: a band behind the Requests spark and chart where the rate jumped, not an alert |

| [0057](0057-a-kafka-cluster-as-it-is.md) | a Kafka cluster as it is, found, and a message through it: Kafka clusters found from kafka_exporter's series as stores; on a Kafka store's page, brokers as columns with the controller, partitions with leaders and followers, every topic, consumer groups with lag per partition; and one message followed by its trace to the partition and offset it was written to and each group that has or has not read it yet |

| [0061](0061-a-demo-with-nothing-but-estate.md) | a demo with nothing but Estate: `bun examples/demo/run.ts` starts Estate against one process playing every tool for a grocer's estate in two environments, staging well and production with a broker gone, a group behind, a database replica behind, traffic that rises and falls, an incident with its comments, a message followed and Ask AI's canned answer |
